# Burnout 3 Playlist Studio — native UI decisions

Primary task: assemble a real MP3 playlist, review metadata/order, audition it, then expose its folder to Takedawn. Start with an empty persisted library, never simulated downloads or fabricated progress.

Three structures considered: (1) import wizard, useful for first-time setup but slow for repeated metadata review; (2) album-art wall, useful for browsing but weak for order and unavailable artwork; (3) pit wall, selected: playlist rail, ordered track table, metadata/lyrics inspector and persistent transport. Every visible region supports selection, review or playback rather than dashboard metrics.

Direction: asphalt/charcoal, burnt orange primary actions, restrained red failures, warm white text. Bahnschrift display headings and Segoe UI body/table. Functional native control surfaces; no artificial album art, logos or racing illustrations. Dense rows, explicit empty state and actual job messages. Main window can resize; inspector scrolls while transport remains accessible. Keyboard/table selection and explicit cancel/retry stay available.

App icon: original B3 raster generated with ImageGen, retained as `Assets/Studio.png`, mechanically converted to a multi-size ICO (16–256) for the executable/window. It contains no EA/Spotify logo. A small native orange header rule provides racing identity without external game assets.

Feedback: selection and search update immediately without losing playlist/filter; playback ticks update only time/progress; imports/downloads report actual service stages and support cancellation. Errors preserve inputs. Native desktop application: Anime.js, browser motion and a 390px web viewport do not apply. No decorative animation is needed.

Exclusive activation update: “Carregar playlist” requires every track to have a prepared local MP3 with no pending metadata. “Baixar e carregar” first prepares the complete playlist and activates only after success. The Core owns the isolated export, config/backup and single-playlist checks. UI badges describe configuration for a future execution or manual X/A selection, never observed in-game playback. Version/file checks and active audio hashes run away from the UI thread. Takedawn can be selected without executing it; its path is kept only in portable `data/ui-settings.json`. The update button opens the official releases page without installing. Generic multi-playlist folder configuration was removed from the UI to preserve exclusivity.

Owner: App UI agent. Core contracts, persistence, downloader/catalog integration and build/release documents belong to the main/Core agents. The initial library flow was inspected separately; evidence for the notification feature is recorded below.

## Now-playing notification — 1.1.0

Preserved the approved native B3 typography, charcoal/warm-white palette and orange slanted accent. The external lower-left HUD has two music lines and an original CUSTOM TRAX signature; no copied EA logo. It follows the visible foreground Takedawn client area and aborts when the available area is too small. A new notification replaces the previous content and restarts its six-second lifetime. Foreground loss/minimization hides it. Native layered/no-activate/click-through window styles keep input with the target; the popup has no manager owner, so minimizing the manager does not stop the watcher.

The functional fade uses a disposable WinForms timer, with immediate presentation when Windows client-area animations are disabled. Anime.js and 390px browser validation are inapplicable to this Windows-native surface. Checkbox changes apply immediately, persist only in portable UI preferences and start/stop the background Core watcher. Closing disposes the watcher and HUD. The demonstration button is explicitly labeled, uses invented music data and does not require or launch a game. Production notifications use Core file-handle events; no diagnostic logging is enabled.

Desktop evidence, 12 November 2026: CUA verified the demonstration controls and preference off/on states; portable preference JSON changed false then true and was restored enabled. A DPI-aware read-only capture measured the native HUD visible with the manager still foreground, alpha 240, then hidden after 5,999 ms. The screenshot `../docs/screenshots/now-playing-preview.png` shows the demonstration at 300% display scaling. `../docs/screenshots/library.png` shows the 1.1 controls at a 1250×667 screenshot viewport, four explicitly synthetic tracks, selected Coastal Run and sandbox configuration for the next execution. Activation was confined to the supplied sandbox configuration. No game was started, changed or observed playing.

Limits: actual in-game positioning, exclusive fullscreen composition, game focus transitions and playback-event timing remain unverified in a running Takedawn session. Click-through and reduced-motion branches were reviewed in source; no interactive game click-through test or Windows animation preference change was performed. Core's independent detector tests are reported by its owner, separately from this UI evidence.

## Linked sources and automatic preparation

Preserved the existing native pit-wall presentation. Import confirmation now says “Adicionar e preparar”; import, metadata/version changes, reordering and removals prepare the local library automatically. “Atualizar” explicitly refreshes the linked remote source, while those local edits use `refreshRemote: false`. “Usar no jogo” prepares before activation. The former download actions were removed. The source dialog can link, replace or unlink a URL without inventing provenance for older playlists. Source type, URL, last query, completeness/warnings and pending activation are available in the inspector and tooltips. A removal explains managed-file cleanup, preserved local originals and possible reappearance from the remote source.

The optional Spotify API token uses a masked field and a per-playlist session-only dictionary; cancel does not bind a source or update that dictionary. Dialog disposal clears the token field and manager closure clears the dictionary. It is never written to preferences, tooltips or drafts. Public Spotify access is described as potentially partial, with remote deletions suspended in that case. A 30-second timer retries only pending local work through the serialized operation/cancellation pipeline; it never polls remote playlists. Core retains responsibility for game-running guards, deletion provenance, completeness and safe activation.

CUA validation, 12 November 2026, isolated demonstration data: created a new playlist; imported one original synthetic 12-second MP3 and observed automatic preparation reach “MP3 disponível”, one ready and zero failures without another button; edited title/artist/album and observed automatic preparation return ready. Opened the source dialog, entered an explicitly demonstrative URL with an empty masked token, and cancelled; persisted source remained null. “Usar no jogo” configured only the explicitly supplied sandbox settings and an export beneath that sandbox's data/active directory. Removing the demonstration track returned the grid to empty, removed its managed MP3, cleared the sandbox active record/audio keys, and preserved the original MP3 SHA-256. The preview was closed normally. No game was started, closed or modified by this validation.
