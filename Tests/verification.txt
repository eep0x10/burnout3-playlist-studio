New API: DetectTakedawn(executablePath?), ActivatePlaylistAsync(playlistId,configPath?,version?,cancellationToken,executablePath?), GetActiveStatus(configPath?). The optional executable path preserves conservative unknown-version behaviour for a user-located custom executable rather than silently falling back to another installed copy.

Activation requires a nonempty playlist and every current track downloaded, present and free of pending metadata changes. It exports a fresh flat isolated snapshot containing only the selected MP3s/sidecars, verifies exact IDs/order/count/hashes and rejects unexpected supported audio. Identical existing snapshots are reused when playlist name, order and source hashes are unchanged and the export is still clean. Contaminated/changed old snapshots are retained, never purged or used as active; a new clean snapshot is made. The ordinary library export root preference remains unchanged.

Version <=0.2.0 or unknown: writes only custom_music_dir to the selected isolated folder and returns explicit EA GAMES TRAX X/A manual-selection instructions. It does not claim current playback or automatic activation. Known version >=0.2.1: one backed-up atomic TOML write additionally sets custom_music_at_start=true and custom_music_soundtrack to the actual ASCII folder name, at most31 display characters, as a string (not an index). This configures selection at the next race; it does not force a user's current in-game selection continuously.

Active status reads the saved selected version, verifies configured directory/autostart/textual name, detects changed or duplicate audio config sections, dropped extra audio, changed hashes, missing tracks, library reorder/removal and pending metadata. It reports configuration/files readiness separately from audible gameplay. ActivePlaylistId is available on LibrarySnapshot.

Transaction failure proof: after a valid reusable activation, the test holds library.json open read-only with FileShare.Read, allowing reads/config write but rejecting the final atomic library replacement. Activation throws; the exact prior TOML bytes are restored only if the config still matches this operation's written hash, and the previous persisted active version/state remains intact. External subsequent config edits are never overwritten by rollback. Reparse-point guards validate the active path from the full DataDirectory boundary.
